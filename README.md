How it works — full walkthrough on localhost</h2><p>This is the whole engine, end to end. Read it once and there is nothing hidden left.</p><h3>8.1 Start</h3><pre><code class="language-bash">python3 adhi.phishkit.py -p 8080 --local</code></pre><p><code>main()</code> parses the flags, writes <code>config.json</code>, creates <code>data/</code>, <code>bin/</code> and <code>data/uploads/</code>, opens <code>data/adhi.db</code>, applies the schema and any pending column migrations, resolves the LAN IP for the banner, then binds a threaded HTTP server on <code>0.0.0.0:8080</code>.</p><p>Every request becomes its own thread. There is no request queue and no worker pool to tune.</p><h3>8.2 Routes</h3><p>The router is a single <code>do_GET</code> / <code>do_POST</code> pair. Paths split four ways:</p><table><tr><th align="left">Prefix</th><th align="left">Purpose</th></tr><tr><td><code>/admin…</code></td><td>Console, session dumps, CSV export, JSON API. Cookie-gated.</td></tr><tr><td><code>/a/&lt;token&gt;</code></td><td>Live panel for one session.</td></tr><tr><td><code>/m/&lt;file&gt;</code></td><td>Media out of <code>data/uploads/</code>.</td></tr><tr><td><code>/&lt;anything&gt;/&lt;token&gt;</code></td><td>A victim link. The middle segment is cosmetic — only the token is authoritative.</td></tr></table><p>That last one matters: <code>/netbanking.hdfcbank.com/login/&lt;token&gt;</code> and <code>/hdfc/&lt;token&gt;</code> resolve to the same session. The vanity path is decoration you control.</p><h3>8.3 Minting a link</h3><p>In the console you pick a kit, optionally edit the disguise path, optionally set a device mode and a quantity, then press <b>Generate link</b>.</p><p><code>POST /admin/api/link</code> writes the vanity path into <code>config.json</code>, marks the kit as last-used, and for each unit:</p><ol><li>generates a 7-byte URL-safe token with <code>secrets.token_urlsafe</code></li><li>inserts a <code>sessions</code> row — site, IP, User-Agent, full header JSON, device, sensitivity flag, OTP flag, optional expiry from <code>ttl</code>, optional visit cap from <code>maxv</code>, burn flag</li><li>if the kit is a gift-code category, mints a unique 12-character code for it</li><li>returns <code>&lt;public_url&gt;/&lt;slug&gt;/&lt;token&gt;</code></li></ol><p>No files are written per session. The row <i>is</i> the session.</p><h3>8.4 The victim arrives</h3><p><code>GET /&lt;slug&gt;/&lt;token&gt;</code> → <code>serve()</code>:</p><ol><li><b>Token lookup.</b> Unknown token → 404 page.</li><li><b>Gate check</b> in this order — expired? visit cap reached? burned? bot? geo-fenced out? Each rejection writes an <code>events</code> row with the reason and bounces the victim to the real site, so a crawler sees a normal redirect instead of a clone.</li><li><b>Device resolution.</b> <code>?d=mobile</code> / <code>?d=laptop</code> wins. Otherwise the stored device. Otherwise <code>auto_dev()</code> reads the User-Agent: iPad / tablet / Android-without-"mobile" → laptop layout, anything matching <code>mobi|android|iphone|ipod|windows phone</code> → mobile layout, everything else → desktop.</li><li><b>Hit counter</b> increments.</li><li><b>Step resolution.</b> The kit's flow is a fixed ordered list, e.g. <code>["login","card","otp","pin"]</code>. If the kit's OTP toggle is off, the <code>otp</code> step is skipped transparently.</li><li><b>Render.</b> The layout family is chosen from <code>LAYOUT</code>, the flow step decides which field block goes in, <code>theme()</code> derives a light or dark palette from the kit's background colour, and the page is returned with a live countdown chip if a TTL was set.</li></ol><p>Each kit is a replica of the <i>shape</i> of the real flow, not a byte-for-byte mirror: brand mark, real copy tone, real field order, real button wording, real footer.</p><h3>8.5 Submitting a step</h3><p>The form posts to <code>/t/&lt;token&gt;/&lt;site&gt;/&lt;step&gt;</code>. <code>_p()</code>:</p><ol><li>Parses <code>application/x-www-form-urlencoded</code> or <code>multipart/form-data</code> by hand (stdlib only).</li><li>Keeps only the fields that belong to the step — <code>ident</code>, <code>pw</code>, <code>otp</code>, <code>card</code>, <code>exp</code>, <code>cvv</code>, <code>pin</code>, <code>holder</code>, <code>seed</code>, <code>dob</code>, <code>addr</code>, <code>zip</code>, <code>ssn</code>, <code>amount</code>, <code>tenure</code>, <code>purpose</code>, <code>name</code>, <code>pan</code>, <code>aadhaar</code>, <code>city</code>, <code>state</code>, <code>emp</code>, <code>income</code>, <code>email</code>, <code>acct</code>, <code>ifsc</code>, <code>bname</code>, <code>extra</code>.</li><li><code>UPDATE</code>s the session row.</li><li>Prints a framed block to your terminal, pushes a formatted Telegram message, and appends an <code>events</code> row.</li><li>Advances to the next step and returns that step's HTML inline — no redirect, no page reload, so the URL never changes and the flow feels native.</li><li>On the last step: status becomes <code>done</code>, and the victim gets either the real site (if <code>instant</code>) or a "verified successfully" screen that bounces to the real site after 2.4 s.</li></ol><h3>8.6 Closing</h3><p><code>Ctrl+C</code>. The watchdog flag drops, the tunnel process group is signalled, the socket closes.
